# Прошивки ARBITER

ARBITER — ориентационный фильтр (AHRS) для 9-осевых MARG-датчиков:
гироскоп, акселерометр, магнитометр. В этом каталоге находятся
платформонезависимое ядро на C99 и готовые пакеты для Arduino, ESP-IDF и
STM32 HAL, каждый с примерами.

## Кратко об алгоритме

Фильтр интегрирует гироскоп, а отсчёты акселерометра и магнитометра
трактует как запросы на коррекцию. Запрос проходит три теста
согласованности (норма удельной силы, невязка теоремы переноса, норма и
наклонение магнитного поля относительно обучаемых онлайн эталонов) и
заряжает пер-сенсорный накопитель доказательств; коррекции включаются
порогом с гистерезисом по этому накопителю. Величина каждой коррекции
расходуется из токен-бакета, пополняемого со скоростью ожидаемого дрейфа
гироскопа. Вследствие этого суммарный поворот, который коррекции могут
внести на любом интервале времени, ограничен ёмкостью бакета плюс
интегралом скорости пополнения. Измерение, обманувшее все тесты, всё
равно не может увести оценку быстрее, чем задрейфовал бы сам гироскоп.

Коррекции наклона выполняются вокруг осей, ортогональных вертикали, а
коррекции курса — вокруг вертикали, поэтому отказ магнитометра не
искажает крен и тангаж. Смещение нуля гироскопа измеряется напрямую в
обнаруженном покое, а не накапливается из интеграла ошибки. Полный
вывод, результаты сравнения (синтетический сценарий и 39 испытаний
набора BROAD) и абляционное исследование приведены в рукописи статьи в
родительском проекте.

Числа, существенные для прошивки: 25 скалярных состояний (около 120 Б),
без динамической памяти, без матричных операций, примерно 270 операций с
плавающей точкой плюс 4 `sqrtf`, 3 `expf` и 2 `atan2f` на шаг, всюду
float32.

## Структура каталога

```
firmware/
├── core/                 платформонезависимый эталон (arbiter.h/.c)
├── arduino/              библиотека Arduino (формат library.properties)
│   ├── src/              обёртка ArbiterAHRS.h + копия ядра
│   └── examples/
│       ├── NoHardware_Selftest/   работает без датчиков
│       └── Basic_MPU9250/         MPU-9250 по I2C (Wire)
├── esp32/                компонент ESP-IDF
│   ├── include/, arbiter.c, CMakeLists.txt, idf_component.yml
│   └── examples/basic/   самотест + опциональная задача MPU-9250
└── stm32/                копия ядра + примеры HAL
    └── examples/
        ├── selftest_main.c        без датчиков, тайминг через DWT
        └── mpu9250_f4_main.c      MPU-9250 на STM32F4 (CubeMX + HAL)
```

Четыре копии `arbiter.h`/`arbiter.c` идентичны; источником истины
является `core/`. После изменения ядра скопируйте его в три платформенных
каталога заново.

## Контракт входных данных

| Вход | Единицы | Примечание |
|---|---|---|
| гироскоп | рад/с | ничего не вычитайте: смещение нуля фильтр оценивает сам |
| акселерометр | м/с² | удельная сила: +9.81 по Z в покое горизонтально |
| магнитометр | любые согласованные | мкТл, гаусс или отсчёты АЦП; используются направление и относительная норма |
| dt | с | измеренный интервал с прошлого вызова; джиттер допустим |

Отсутствующий отсчёт магнитометра передаётся как `0,0,0` или `NAN`;
на этом шаге фильтр работает в 6-осевом режиме, и курс дрейфует с
остаточной скоростью гироскопа. Магнитометр должен быть заранее
откалиброван от hard/soft-iron: фильтр отбраковывает помехи среды, но не
калибрует датчик. Оси всех трёх датчиков должны образовывать одну правую
связанную систему координат; переназначение осей AK8963 показано в
примерах для MPU-9250.

## Быстрый старт

### Arduino (любое ядро: AVR, SAMD, RP2040, ESP32-Arduino, STM32duino)

Скопируйте `firmware/arduino/` в папку `libraries/` вашего скетчбука под
именем `ArbiterAHRS`, перезапустите IDE и откройте
Файл → Примеры → ArbiterAHRS → NoHardware_Selftest. Скетч печатает PASS
при сходимости на синтетических данных; ожидаемая точность указана в
шапке скетча. `Basic_MPU9250` показывает работу с живым датчиком.

Минимальное использование:

```cpp
#include <ArbiterAHRS.h>
ArbiterAHRS ahrs;

void setup() { ahrs.begin(); }

void loop() {
    // gx..gz рад/с, ax..az м/с^2, mx..mz любые единицы, dt секунды
    ahrs.update(gx, gy, gz, ax, ay, az, mx, my, mz, dt);
    float roll, pitch, yaw;
    ahrs.getEulerDeg(roll, pitch, yaw);
}
```

### ESP-IDF (ESP32, S2, S3, C3)

Скопируйте `firmware/esp32/` в `<проект>/components/arbiter` и добавьте
`arbiter` в `REQUIRES` главного компонента, либо соберите пример:

```sh
cd firmware/esp32/examples/basic
idf.py set-target esp32
idf.py build flash monitor
```

Пример выполняет самотест при загрузке и печатает измеренное время шага
на вашем кристалле. Для задачи с живым датчиком установите
`RUN_LIVE_MPU9250` в 1 в `main.c` (SDA 21, SCL 22 по умолчанию).

### STM32 (HAL / CubeMX)

Добавьте `stm32/arbiter.c` и `stm32/arbiter.h` в проект CubeMX. Для
первой проверки добавьте `examples/selftest_main.c` и вызовите
`arbiter_selftest()` после настройки тактирования; функция сообщает
ориентацию, восстановленное смещение нуля и среднее число тактов на шаг
через счётчик DWT. `examples/mpu9250_f4_main.c` — законченный главный
цикл для MPU-9250 на I2C1 с выводом в UART; замените помеченные строки
вызовами инициализации, сгенерированными CubeMX для вашей платы.

## API (ядро C)

| Функция | Назначение |
|---|---|
| `arbiter_default_params(ArbiterParams *p)` | заполнить `p` опубликованными значениями по умолчанию |
| `arbiter_init(ArbiterState *s, const ArbiterParams *p)` | сброс состояния; `p` должен жить дольше `s` |
| `arbiter_update(s, gx, gy, gz, ax, ay, az, mx, my, mz, dt)` | один шаг комплексирования |
| `arbiter_euler(s, &roll, &pitch, &yaw)` | углы Эйлера ZYX, рад |
| `s->q[4]` | кватернион, связанная система → восток-север-верх, Гамильтон `[w x y z]` |
| `s->b[3]` | оценка смещения нуля гироскопа, рад/с |
| `s->gate_a`, `s->gate_m` | акселерометр / магнитометр сейчас доверены |
| `s->flag_dyn`, `s->flag_mag` | флаги динамического ускорения / магнитной помехи |
| `s->is_static` | состояние детектора покоя |

Обёртка Arduino (`ArbiterAHRS.h`) даёт ту же функциональность в виде
класса: `update()`, `updateIMU()`, `getQuaternion()`, `getEulerDeg()` и
диагностические геттеры.

## Параметры

`arbiter_default_params()` задаёт значения, которые показали себя на
синтетическом бенчмарке и BROAD без подстройки под набор данных.
Точность определяют два параметра:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `rho0` | 0.3 °/с | базовая скорость пополнения бюджетов коррекции; увеличьте для гироскопов с худшей стабильностью нуля |
| `diff_tol` | 0.8 рад/с | допуск теста теоремы переноса акселерометра; уменьшите для механически чистых установок |

Остальные поля описаны в `arbiter.h`. `cap_tilt` и `cap_yaw`
ограничивают одиночный шаг перепривязки после периода недоверия;
`ev_up_tau_mag` задаёт, насколько медленно возвращается доверие к
магнитометру. Один результат абляции стоит знать: на данных с умеренными
помехами отключение жёстких ворот (установите `gate_hi` в 0, чтобы
ворота оставались открытыми) при сохранении бюджета улучшило точность в
нашем бенчмарке. Оставляйте ворота включёнными для сред с сильными
магнитными или инерциальными помехами.

## Ресурсы

Состояние: около 120 Б ОЗУ на экземпляр фильтра плюс около 100 Б на блок
параметров. Код: несколько килобайт в зависимости от тулчейна.
Измеренное время шага печатают самотесты; аналитические оценки: 3–5 мкс
на Cortex-M7 при 216 МГц, 8–12 мкс на Cortex-M4F при 168 МГц, 15–25 мкс
на ESP32, 150–250 мкс на Cortex-M3 с программной плавающей точкой и
1.5–2.5 мс на 8-битном AVR. На AVR предпочтителен 6-осевой режим и
частоты до примерно 200 Гц.

## Валидация

Примеры-самотесты воспроизводят статический случай сходимости с
известной истиной: фиксированная ориентация, начальная ошибка курса 30°
и заложенное смещение нуля гироскопа. Ожидаемый результат — ошибка
ориентации ниже 1.5° и ошибка смещения нуля ниже 0.15 °/с через 20 с при
250 Гц. Прогоните самотест на вашей платформе до работы с живыми
данными: он проходит весь код фильтра и сообщает реальную стоимость шага
на вашей аппаратуре.

## Известные ограничения

Курс ненаблюдаем без магнитометра и в 6-осевом режиме дрейфует со
скоростью остаточного смещения нуля. Смещение нуля измеряется только в
обнаруженном покое; приложения без пауз накапливают дрейф, под который
рассчитан бюджет. Длительное когерентное ускорение, удерживающее норму
удельной силы около g, проходит диагностику и уводит наклон с бюджетной
скоростью; это спроектированный худший случай.
